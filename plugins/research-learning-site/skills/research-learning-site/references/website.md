# 学习网站实现与交付

## 项目选择与设计

维护已有网站时先读取项目说明、路由、集合 schema、构建脚本和托管工作流，保留已验证的接口。新站无框架偏好时，Markdown 静态生成适合这类材料；Astro 可以作为选项，现有文档框架也可以采用。不要因为 Skill 来自某个 Astro 项目就强制所有新项目使用它。

先选一章基础、一篇精读和一张课程页作为真实样例，确定字号、行距、章节位置、目录、表图与手机行为。用户给的样式链接应实际查看；渐进出现可以增强层次，但内容不能依赖动画完成才能阅读。尊重减少动效，使用已有品牌和主题优先。

如需复用公开起点，可检查 [Token Economy Lab 代码](https://github.com/Token-Economy-Lab/Token-Economy-Lab) 的当前版本、许可、依赖和示例，再决定使用范围。它只是实现参考，不是预配置的新项目身份或固定部署目标。不要复制其私有研究库。

## 内容契约与路由

通用元信息建议覆盖：ID、类型、主题、层级、标题、简介、更新日期、发布状态、阅读时间、学习时间、课程、顺序、产出与前置。模板采用与该实现相近的字段；已有项目字段不同则显式映射。`status` 可以是审阅标记，不能替代 `publish`。

按课程顺序排序，不依赖文件枚举顺序或更新时间。材料 ID 不随标题变动，重命名提供旧链接处理。一个专题允许多篇材料，章节数与站点路由从发布集合生成，不固定为某次项目的页数。

校验前置引用存在且可见、同课程前置在前、依赖没有循环、课程内顺序不重复、产出非空；草稿不能出现在页面、导航、相关阅读、索引或静态搜索资源。导入旧笔记时兼容旧字段，逐步补元信息，不破坏原页面。

## 密码与保密材料

先落实用户要求的保密等级。若只是控制网页入口，可用适当访问门；若正文也需保密，不能只隐藏 DOM 或公开明文 JSON 后检查密码。优先选择有服务端鉴权的托管，或采用经验证的静态加密方案。

静态发布可以分离为：公开的通用代码/例子、私有的真实内容/构建、公开的加密发布文件。公开代码使用审查过的历史；含私人内容的旧历史留在私有仓库。只有口令加密适合用户已接受的访问模型时才使用，不能声称等同企业身份管理。

正式构建缺少内容或密钥时应失败，不能回退到明文发布。正文及标题、简介、产出、课程和搜索数据一同保护。生成缓存、来源 PDF、内部附件、调试截图、明文日志与 secrets 不作为公开产物。密钥在目标环境的 secret 管理中配置，不写入 Skill、Git 或示例。

若用 GitHub Pages，账户/组织根域名由 `<owner>.github.io` 发布仓库决定；项目站使用仓库路径。域名、base path、资源和导航要与实际托管一致。更改组织级设置、迁移仓库或切换旧站不是每次任务默认步骤。

## 自动发布

公开代码 PR 与主分支先构建示例并做代码审查；只有检查通过的代码版本才能进入私有正式构建。触发携带不可变 commit SHA，私有构建验证它来自批准的分支及成功检查。真实内容变化也触发构建，保留手动入口。

跨仓库触发与部署采用最小范围凭据，分别管理；不要为方便使用个人全权限 token。日志只写检查结果与必要版本信息；不得上传明文调试包。部署前执行草稿、资源与明文泄漏门禁。

网页上线需要用户当前任务授权；已有授权继续有效。缺授权时先完成可审查结果再问，不把整个技能设置为无条件自动发布。无需访问 GitHub 时，不强制它成为所有项目的外部依赖。

## 验收与修订

实际执行和记录：

| 范围 | 验收重点 |
| --- | --- |
| 材料 | 事实位置、来源版本、教学算例、运行输出与证据状态 |
| 构建 | 预期路由、资源、内部 href 和锚点、先修关系、草稿排除 |
| 阅读 | 课程顺序、论文组序、当前章、上一/下一章、折叠选读 |
| 视觉 | 桌面和窄手机、长标题、代码与表格、图中标签、局部滚动 |
| 交互 | 键盘、手机两级目录、减少动效；密码错误/成功/记住/锁定如适用 |
| 保密 | 公开全部可达分支和标签、生成产物、日志和元信息；避免输出命中秘密 |
| 发布 | 代码触发和内容触发各一次成功，真实域名及部署版本核对 |

尽量复用现有可执行验收脚本；新材料扩大实际路由清单。页面数量变化后旧的固定数量测试不应成为盲区。浏览器截图和机制原图应实际查看，不能把“文件存在”当视觉验收。

反馈修订先识别可操作问题，再改变课程或机制，保留审阅和版本记录。发布后给学习入口、材料位置、通过的检查及尚无实测的边界，避免罗列无关构建细节。
