# 将研究资料组织成课程

## 两类读者共用证据，各自有完成标准

入门者的出口是能解释、计算和选择；研究者的出口是能复述方法的操作过程、限定结论、设计对照并推进验证。先确认“入门”是研究方向入门还是完全没有模型基础，不能默认所有新人都懂术语。

组织共同基础与若干专题，每个专题从机制走到代表方法、系统/业务和比较。入门顺序由先修依赖决定，研究者可以从比较或原论文进入。章节量由知识缺口决定；不要为了覆盖每篇候选论文制造一页。

每章至少有稳定 ID、所属课程、顺序、前置条目、学习产出和下一步。前置应是理解当前章确实必要的材料。避免所有章都依赖总学习地图，再由地图反向依赖所有章造成循环。

## 教学结构

机制章节按“问题 → 最小例子 → 机制图 → 必要公式 → 正常/失败情形 → 自测与答案 → 延伸阅读”展开。图中对象与算例变量一致；不能先堆注意事项再要求新人自行拼出机制。

选一个贯穿例子反复改变条件，展示因果。例如：共享前缀只改一个早期 Token；缓存容量缩小；预测高置信度但实际准确率低；预算判断器自身花钱；摘要遗漏一个工具返回字段。每次说明哪些因素固定、改变了什么和为何产生差异。

公式标单位、分子与分母，并给完整代入。性能比例、百分点与成功任务成本不要混用。解释不应只剩几个定义，也不必无条件推导读者用不到的数学。

精读的六项教学结构见 `references/research.md`；教程、系统、案例和比较选择对应 `assets/` 模板。模板提供提醒，写作时删掉无关栏位和填充提示，增加能帮助理解的具体内容。

## 实践要有可核验的出口

优先设计无需付费 API 或专用设备的回放，适用于建立机制直觉；需要真实模型行为的结论另做实验。提供冻结的小数据、依赖和运行方法、预期输出、解答以及至少一项容易犯错的变体。

程序应验证真实的学习不变量：例如总账是否漏算失败任务、分页容量是否包含最后一页空槽、预算前沿分母是否包含失败样本。避免只检查标题或复制实现的无意义断言。运行过后保存输出与结论，不能因为代码看上去合理就标“已运行”。

业务案例选择可验收的任务：正确回答并给来源、定位故障并提供可验证证据、修复代码并通过冻结测试等。用验收标准推动成本归因和策略选择，不用虚构“某企业提高百分之多少”。

系统材料提供先在纸面/标准库回放能看到的机制，再写真实部署的环境、版本、关键参数和观测字段。回放没有证明产品性能，真实实验结果也不能自动推广到所有任务。

## 可持续的学习导航

全站课程负责选择方向；课程目录负责先后；当前文章目录负责定位。正文顶部显示先修和学习产出，底部明确下一篇必读，旁边给少量有理由的选读；其余关联资料折叠或放到完整索引。

阅读分钟数只表示阅读预计时长。完成练习、阅读原图和复查源文需要单独给学习时间；数字是估计而非能力承诺。研究者入口应直接连接条件表、比较、证据和实验设计。

验收时模拟新人走完整路径：能否理解术语、做出一个算例、选一个策略、找到下一章。模拟研究者从一项比较回到原始图表：能否知道实验条件、识别没有证据的部分、写出具体基线。图表及导航需在手机上可使用。
