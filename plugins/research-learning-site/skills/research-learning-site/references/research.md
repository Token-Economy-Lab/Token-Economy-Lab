# 文献与证据工作

## 从任务得到检索策略

把宽主题转成可检索的问题轴：要优化什么，质量约束是什么，发生在单次调用、任务轨迹还是服务系统，允许控制哪些环节。记录暂不覆盖的范围。种子论文提供机制入口；从引用、后续工作、作者代码和系统文档扩展。分类缺口比总篇数更有用。

资料截止日是输入参数。默认采用执行当天的用户时区日期，除非用户设定固定范围；较晚版本要另列，不能悄悄并入早期范围。新论文标识证据成熟度；综述帮助找路线，关键实验仍追溯原始工作。重复资料按论文身份合并，但允许跨专题关联。

用 `assets/source-register.md` 保存检索账。缺全文、只有元信息、作者结果已核对、独立复现分别写入状态，不用一个“已读”字段掩盖差异。下载来源文件前尊重目标目录与使用范围，资料附件不自动进入网页。

## 精读要重建的内容

精读不是扩写摘要。依次回答：原先哪里失败，方法观察了什么，状态怎样变化，决策与执行如何衔接，训练或控制器额外做了什么，论文通过哪些对照支持结论。用自己的流程图配合伪代码，保留关键分支，不画出论文不存在的顺序。

正文给原图的编号、版本、横纵轴、基线和条件，并解释读者应从图中读出什么。可以概念重绘；重绘应注明非原图、非实测。引用图像时遵守原来源的使用要求，不要把下载权限当成无限复制权限。

最低可用精读结构：

| 部分 | 应解决的问题 |
| --- | --- |
| 准确身份 | 标题、作者、版本、发表状态、原始链接与读取日期是否可追溯 |
| 机制 | 输入、状态、训练/决策、执行与终止分别是什么 |
| 条件表 | 数据划分、模型、设备、并发、输入输出长度、预算与基线 |
| 关键结果 | 一项有原文位置的结论，如何解释数值及其分母 |
| 开销 | 数据生成、训练、评分、额外调用、搬运、验证和失败成本 |
| 失效情形 | 哪个假设被破坏，结果可能下降或无法迁移 |
| 可执行对照 | 固定样本、简单基线、评价器、记录字段和否证条件 |

无需为填模板编造未公开的细节。标“原文未报告”，说明它妨碍哪个判断。

## 比较与批判

明确作者实验支持的范围，再讨论项目相关性。限制分析要区分作者承认的限制、由实验设计推得的风险、尚未验证的猜想。不要因为方法复杂就断言低效，也不要因为单个负例就否定整条路线。

常见不可直接比较的项目包括：不同模型/tokenizer、不同硬件与并发、答案质量口径、pass@1 与 pass@k、均值与尾部、理想 warm cache 与冷启动、单请求费用与完整成功任务成本、训练成本是否摊销。比较表应暴露这些差异；不能对原论文最大加速比排序后称最优。

对于 Agent，计入工具响应进入后续上下文、多轮历史重发、失败和重试、预算判断与验证。对于缓存和服务系统，区分逻辑 Token、真正重算的工作、缓存管理/传输和排队。对于推理预算，区分生成上限、思考策略、任务限制与共享算力约束。这些是研究轴的示例，并非对所有领域强制使用 Token 指标。

## 从证据到下一项研究

提出问题时写出：已经知道什么；哪个条件证据不足；拟检验的预测；便宜且合理的基线；冻结或受控样本；主要和副作用指标；什么结果会推翻预测。先让简单基线参与竞争，再增加复杂机制。

实测记录保留环境、输入、代码版本、原始输出与失败样本。独立复现意味着重新运行论文相关实验，不是浏览作者代码、运行教学算例或看到官方演示。维护新证据时更新相关课程、比较和覆盖表，同时保留旧版本与更正理由。
